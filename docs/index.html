JUST IN New on the shelf What version 1.1 just added

The short version of the release, no changelog reading required.

  • Two agents can now work the same open deck. Live calls into PowerPoint run one at a time, so agents editing together take turns instead of overwriting each other. And if PowerPoint throws up a dialog only a human can answer, the server says so instead of hanging. Both safeguards were proven on the Word server first.
  • Fixed: your warning prompts stayed off. The server mutes PowerPoint's warning dialogs while it edits, which is fine, but it used to forget to unmute them on the way out. You'd close the session and PowerPoint would keep swallowing warnings meant for you. It always turns them back on now.
  • Six packs instead of nine. The smallest packs cost more tokens to skim past than they saved, so they've been folded into their neighbors. Sessions start lighter, and every old pack name still works.
  • Bad slide lists get caught before PowerPoint opens. Ask the exporter for slides that don't exist, or hand it a malformed list, and it used to spend nine seconds opening PowerPoint just to fail with a cryptic error. Now it checks the request first and tells you exactly what to fix.
DEPT. 00

Move the node, the arrows follow

Every AI pipeline can put a diagram on a slide. Almost all of them hand you a picture of one: flat pixels behind glass. The night before you present, one box needs to move half an inch, and a picture does not care how small the change is. This server draws diagrams the other way: SVG goes in, grouped native PowerPoint shapes come out, with connectors glued to the shapes they join. Drag a node in PowerPoint and the arrows follow. Ask the agent to recolor one box by name and only that box changes. No regeneration round trip, no image API, no PowerPoint install needed to build it.

DEPT. 01

Why this aisle exists

Ask an AI to put an org chart on slide 12. Almost every tool that can draw one hands you a picture of an org chart; the few that draw real boxes only offer fixed layouts, take them or leave them. Then the reorg happens: one name changes, one box moves under a different manager. The box cannot move. It is not a box; it is pixels. Your choices are to regenerate the whole image and hope nothing else shifted, to pay an image service again for the same chart, or to rebuild it by hand, forty minutes of dragging rectangles you did not make.

Shopping around does not save you. The most popular PowerPoint MCP server sits archived: nearly two thousand stars, no successor, and it could add slides but never properly delete, duplicate, or reorder them. The tools that go deeper all need Windows with PowerPoint open before they will do anything at all.

KitchenSink4PPT draws the chart as real PowerPoint shapes: boxes you can drag, connectors that stay attached when you do, text you can click into. The one-name fix takes ten seconds, by you or by the agent, and the arrows follow.

DEPT. 04

The context bill

Every MCP server draws on an agent's context window before any work starts, the way every fixture on the floor draws current whether anyone is looking at it or not. The Word sink published its bill and promised tiered loading for v2; this server ships tiered loading on day one. A session starts from the lite core, 24 tools. When a job needs more, the agent enables the pack by name and the tools appear mid-session. The lazy path is a dead end on purpose: lite carries no degraded stand-ins, and any refusal for out-of-scope work names the exact pack and the exact call that unlocks it. The refusal is the signpost.

24Tools in the lite core
4.5kTokens, lite core up front
1Call to the whole sink
# an agent in lite mode tries structural table work > merge_cells … REFUSED: table structure lives in the tables-charts pack. Run enable_tools(["tables-charts"]) to switch it on. > enable_tools(["tables-charts"]) OK: pack enabled, tools registered, token cost reported.

Power users who want everything loaded from the start can pin it: KS4P_MODE=full in the server environment, or a comma-separated pack list. Administrators can lock the selection with KS4P_PACK_POLICY=locked.

Wiring it in

ORDER FORM № KS4P-1

① GET THE FIXTURE

$ pip install kitchensink4ppt

② WIRE IT UP (Claude Code)

$ claude mcp add ppt -s user -- kitchensink4ppt

③ ANY OTHER MCP CLIENT (stdio)

{ "mcpServers": { "ppt": { "command": "kitchensink4ppt", "env": { "KS4P_MODE": "lite" } // "lite" (default) · "full" · "graphics,design" } } }

File-based tools, which are the large majority, need no PowerPoint installation and run cross-platform. The export and validation tools (PDF, per-slide PNG, opens-clean check) borrow a local Microsoft PowerPoint through COM when one is on the premises. Full setup in the README.

🛡️

Engineered Not to Corrupt

Atomic validated saves. Automatic timestamped backups before every change. Byte-identical passthrough of anything not being edited, so animations, media, and embedded objects pass through untouched. Every release gates on real decks round-tripping byte-clean and opening in PowerPoint without a repair prompt, and on an adversarial round through the raw MCP transport. When a target is ambiguous, the server refuses with candidates rather than guessing; a wrong first match is somebody else's policy.
